# Publishing and files to upload

Public owner: **lonefrogg**. Plugin ID: **`lonefrogg/throne-vpn`**. The account-name configuration script has been removed; no placeholder replacement is needed.

## Your own GitHub repository

Create an empty public repository named `throne-vpn` under `lonefrogg`. Upload the **contents** of the extracted `throne-vpn-release` folder to its root, preserving this layout:

| Upload | Purpose |
| --- | --- |
| `README.md` | Full English installation guide and GitHub landing page |
| `README.ru.md` | Full Russian installation guide |
| `LICENSE` | Repository license |
| `.gitignore` | Private/build-file exclusions |
| `catalog.toml` | Discovery metadata for your standalone Noctalia source |
| `throne-vpn/`, all contents | Plugin manifest, Luau entries, helper, guide, permissions, license, image and translations |
| `docs/` | Publishing, review notes and supporting PR draft |
| `tests/` | Backend and mock-host regression tests |
| `tools/check_release.py` | Packaging checks; the only remaining tool script |
| `.github/workflows/checks.yml` | GitHub Actions checks |

All files shipped in this ZIP are project files intended for the standalone repository. Do not add a parent `throne-vpn-release/` directory around them inside GitHub: `README.md`, `catalog.toml` and `throne-vpn/` should be visible at the repository root.

### Do not add

- API key files, environment files containing secrets or the entire `~/.config/throne` folder.
- Actual Throne profiles, subscriptions, routing/settings databases, exports or backup archives.
- Throne/ThroneCore/thronectl binaries, downloaded release archives or installer temporary files.
- Logs, Python caches, virtual environments, or screenshots/video containing private desktop/profile data.
- The distribution ZIP as the only repository content. Attach it separately to a GitHub Release if desired.

The extracted release does not include those private files. A `.gitignore` cannot remove a secret already committed to Git history.

### Validate and publish

From the extracted repository root:

```sh
python3 -m unittest discover -s tests -v
python3 tools/check_release.py
git init
git branch -M main
git add README.md README.ru.md LICENSE .gitignore .github catalog.toml docs tests tools throne-vpn
git diff --cached --stat
git diff --cached --check
git commit -m "Add Throne VPN plugin for Noctalia"
git remote add origin https://github.com/lonefrogg/throne-vpn.git
git push -u origin main
```

Review staged content before committing/pushing. Use your chosen public Git identity; none is embedded in this archive. MIT uses a neutral contributors credit. Verify your right to publish the material under that license.

Once published, installation is:

```sh
noctalia msg plugins source add throne-vpn git https://github.com/lonefrogg/throne-vpn.git
noctalia msg plugins enable lonefrogg/throne-vpn
```

The root README covers installing Throne 1.4.0-beta.4, thronectl v0.2.0, saving the API key, TUN privileges, ZIP installation and the bar widget. DNS passwordless authorization is an optional manual procedure; no permission rule is applied by installing this plugin.

## Noctalia community catalog

First read the current [community rules](https://github.com/noctalia-dev/community-plugins) and [PR template](https://github.com/noctalia-dev/community-plugins/blob/main/.github/PULL_REQUEST_TEMPLATE.md). The generated-code rule and required attestation must be resolved openly with maintainers; AI disclosure and review do not by themselves make the code non-generated. Keep an unresolved submission Draft.

Before submitting:

1. Test this public package in a real Wayland/Noctalia session: pointer actions, final-row scrolling, search, TUN actions, error states, settings changes, scale and icon state.
2. Replace the illustrative cover with a sanitized real screenshot exported through the [official thumbnail generator](https://assets.noctalia.dev/plugins/thumbnail-generator.html), 960×540 WebP. Attach actual screenshot/video evidence.
3. Fork `noctalia-dev/community-plugins` and branch from `main`. Check the directory name is still available.
4. Copy **only `throne-vpn/`** into the fork's root, retaining all of its contents.
5. Do not copy your root `catalog.toml`, README files, tools/tests/workflow or other plugin directories. The community catalog is generated by CI.
6. Submit one plugin per PR, targeting `main`, using their current template plus truthful details from [PR_DRAFT.md](PR_DRAFT.md).

The core team's `official-plugins` source does not accept third-party plugins. Publication in your own GitHub source does not depend on community acceptance.
